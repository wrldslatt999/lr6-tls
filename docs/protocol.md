# Протокол захищеного обміну

## 1. TLS-сесія

Сервер створює `SSLContext(PROTOCOL_TLS_SERVER)`, налаштовує `TLSVersion.TLSv1_2` як мінімум, читає локальний сертифікат і приватний ключ. Клієнт створює `ssl.create_default_context(Purpose.SERVER_AUTH, cafile='certs/ca.crt')`, обов'язково перевіряє CA, SAN та ім'я `localhost`. Узгоджені версія TLS, шифр і SHA-256 відбиток сертифіката доступні клієнту через `SSLSocket` та виводяться після з'єднання.

Сертифікат `server.crt` підписаний **локальним самопідписаним CA**. Для даного навчального довірчого оточення клієнт явно отримує `ca.crt`; без нього підпис не вважався б довіреним. Публічний CA для localhost не використовується.

## 2. JSON Line повідомлення

Після встановлення TLS всі дані йдуть всередині TLS-з'єднання (UTF-8 JSON + `\n`, фрейм до 64 КіБ). Першим повідомленням обов'язково є `auth`:

```json
{"op":"auth","username":"alice","password":"<entered via hidden prompt>"}
```

При правильному `scrypt`-верифікаторі сервер створює випадковий opaque-токен та випадковий 256-бітний сесійний ключ HMAC. Вони передаються **лише всередині вже захищеного TLS** і **не відображаються в консолі та логах**. Термін дії сесії — 900 с; сесія зберігається тільки в пам'яті сервера. Після цього відправляється:

```text
op=data, token=<session>, seq=1, payload_b64=<base64>, hmac=<hex-HMAC-SHA256>
```

MAC охоплює ASCII-рядок `REQ|{seq}|{payload_b64}`. Сервер перевіряє токен, термін, послідовність, розмір та HMAC. Після успіху повертає `bytes`, `sha256`, `seq` та HMAC відповіді, що обчислюється над `ACK|{seq}|{bytes}|{sha256}`. Клієнт перевіряє і SHA-256 отриманих відомостей, і HMAC підтвердження, не довіряючи лише `ok=true`.

Вихід із сесії: `{"op":"logout"}`. Сервер видаляє токен. Повтор повідомлення зі старим `seq` відхиляється. При неправильному HMAC сервер повертає `bad_hmac`, але не приймає повідомлення.

**Обмеження:** сесійний ключ HMAC передається через TLS. Тому HMAC є додатковим контрольним механізмом на рівні застосунку, **але не незалежною від TLS криптографічною автентифікацією**. Безпека залежить від правильності TLS та захисту клієнтських/серверних процесів. TLS забезпечує конфіденційність та цілісність транспортних даних.
